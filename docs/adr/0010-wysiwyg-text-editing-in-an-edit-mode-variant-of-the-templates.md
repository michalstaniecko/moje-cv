# WYSIWYG text editing in an Edit-mode variant of the Templates, with unchanged document output

Status: proposed – experiment, implemented on `experiment/inline-editing-redesign` (slices S1–S7; decision log, deviations and the questions resolved on 2026-11-15: `docs/specs/wysiwyg-editing.md`). Supersedes the parts of ADR-0009 that rejected in-place text editing and placeholders.

The owner asked that, in Edit mode, CV content is edited directly on the pages, without any content form. We decided that every Template draws the text of CV fields through small editing slots (`template/editable.tsx`): without an editing context (Preview mode, the PDF window, Template thumbnails) a slot returns exactly today's markup, and with the context that `CvPages` receives only from the Edit-mode preview it draws each field as its own editable plain-text span (a Page field; `contenteditable="true"` with the Template's white space – Chromium forces `pre-wrap` on `plaintext-only` – and the editor keeping the text plain) inside the same Template element, with separators such as " – " and ", " as plain text between fields. A line joined from several fields stays one text, exactly as in the PDF, outside the part of the CV holding the focus and splits into its fields when that part gets the focus (a click or Tab into the line puts the caret in the right field): an element boundary inside a line moves the rest of the line by 1/64 px, which the idle Edit-mode pages may not show. So text being edited sits in the real Template layout and wraps exactly as in the PDF, and joined lines (dates, "company – location", "level, field, institution", "label: value") are edited per field. Values that are not text (dates, "currently", the photo, choosing a clause from the library) get small Field popovers next to the field; Edit cards are retired (no code is left of them), and the CV form stays as the full linear alternative. Empty fields show placeholders only in the part of the CV that holds the focus (or was just added), and those placeholders take space: Edit mode paginates like the PDF whenever no field is being edited, and differs only by the active part's placeholders while one is. `generateBlocks` gets an optional `reveal` option for that, which the PDF and DOCX never pass. The preview bar's warnings (page count, "too long", the check before export) always come from the Preview-mode split: while a part is revealed, `CvPages` also measures, without placeholders, just the blocks of that part and those it changes (`domain/previewSplit.ts`) and runs the pure `paginate` a second time (decided 2026-11-15).

Removing a position or an education entry is a `danger` item in the entry handle's menu, after a separator, with "Removed. Undo". This departs from the rule of #111 (user story 14: entries are removed with a text button, not from a row menu, so that a large fragment is not removed by accident) on purpose: that rule is about the rows of the CV form, which keeps its text button. On the pages there is no card, so the menu is the only visible place, and the separator, the `danger` style and the undo notice are the protection.

## Considered Options

- **`contenteditable` on today's Template nodes**: rejected. One node often carries several fields, so edits cannot be mapped back to fields, and React would overwrite the text on every render.
- **A text field laid over the text on the page**: rejected again (ADR-0009): it wraps differently from the Template and leaves joined lines unsolved.
- **Separate editable copies of the Template components**: rejected. Two copies of three Templates drift apart, and every drift is a lie about what the PDF will look like.
- **Placeholders for every empty field in Edit mode** (or none at all): rejected. Always-on placeholders make Edit mode pages permanently differ from the PDF; none leave no place to put the caret for a missing company or date.
- **Keeping blocks mounted across page breaks** to protect the caret: rejected, it changes the structure of `CvPages`; the caret is restored by field key before paint instead.

## Consequences

- "Templates unchanged" now means "document output unchanged", checked by machines: a golden-markup Vitest of every block in every Template without the editing context, the golden pages e2e test in Preview mode, the same baselines for idle Edit mode, and unchanged DOCX tests.
- A new Template must draw field text through the slots; the class contract of ADR-0009 shrinks to what the editing layer still reads (header parts for the contacts handle and the photo button, list rows, dates, the consent clause) – the classes that only told an Edit card which field was clicked are gone.
- Structure stays reachable without the mouse: handles and "+" pills are out of the Tab order, and Shift+F10 in a Page field opens the menu of its handle; changes of structure made from the keyboard are announced in an `aria-live` region.
- In Edit mode the pages are exposed to screen readers as the CV with labelled text fields; in Preview mode they stay hidden.
- ~~The CV form stays permanently, as the linear and accessible way to edit, for the content of hidden sections and for reordering by drag; it is not a temporary fallback.~~ Superseded by ADR-0011 (2026-11-15): the CV form will be removed once the Outline, the pages and the toolbar cover everything it does.
- Typing on the page uses the CV form's undo merge keys, so both produce the same undo steps; the native undo of editable elements is always replaced by the editor's.
